# rem — UI issues (baseline)

_Captured from `test-artifacts/` via the browser-mode screen sweep (`src/test/screens.browser.test.tsx`, real Chromium @ 1280×800)._

Input for the UI redesign sub-project (roadmap #2). Every issue references the screenshot it came from. Severity is rough: **bug** = visibly broken, **polish** = looks unfinished, **note** = worth deciding during redesign.

## What already looks good (keep these)
- Code-block rendering in the editor — dark theme + syntax highlighting reads cleanly (`card-editor-edit.png`).
- Grade buttons — color-coded borders (red/orange/green/blue) with per-button interval previews are clear and useful (`review-answer.png`).
- Card/list surfaces — white rounded rows with a soft shadow are a fine base.

---

## Deck list (`deck-list.png`, `deck-list-empty.png`)
- **bug — "Add deck" button wraps to two lines** ("Add / deck"). In the flex row the button is sized by content and collapses, wrapping the label. Fix: `white-space: nowrap` + `flex-shrink: 0` and enough horizontal padding so it always stays one line.
- **polish — washed-out disabled primary.** The disabled "Add deck" is the indigo accent at `opacity: 0.5`, reading as a faded/low-effort control rather than a deliberate disabled state. Fix: a neutral disabled token (muted gray fill + muted text).
- **polish — weak empty state.** "No decks yet. Create one above to start." is plain centered muted text in a large void — no icon, no hierarchy, no anchor (`deck-list-empty.png`). Fix: stronger empty state (icon/illustration, larger heading, single clear CTA).
- **note — flat deck rows.** Each row is just name + an "N due" badge of equal weight; the "0 due" badge is very muted and easy to miss. Consider richer rows (card count, due as a colored chip only when > 0) and a clearer hover affordance.
- **polish — top-heavy header.** The "rem" wordmark sits in a tall bar with a full-width divider, then a large gap before "Decks"; the top of every screen feels empty.

## Deck detail (`deck-detail.png`, `deck-detail-nothing-due.png`, `deck-detail-empty.png`)
- **bug — "Nothing due" shown for a 0-card deck.** `deck-detail-empty.png` shows a "Nothing due" pill top-right while the body says "No cards yet." Contradictory — nothing *can* be due. Fix: for an empty deck, suppress the study control (or say "No cards").
- **polish — "Nothing due" pill reads as an ambiguous button.** It's a bordered pill at `opacity: 0.5` (inline style) where the "Study (n)" button normally sits, so it looks like a disabled action rather than a status. Fix: render the non-actionable state as plain muted text, not a button shape.
- **note — card rows under-informative.** Rows show only the first line of the front, reuse the exact `.list-row` style as the deck list (blurring the two levels), and give no answer preview / due indicator / edit hint (`deck-detail.png`, `deck-detail-nothing-due.png`).
- **note — primary action emphasis.** "+ Add card" is a plain bordered button next to muted "N cards"; the add action is visually quiet relative to the large "Study" button.

## Card editor (`card-editor-new.png`, `card-editor-edit.png`)
- **polish — uneven inline-code spacing.** In "How to narrow `unknown`?" the inline `unknown` chip leaves an awkward gap before "?" ("narrow  unknown ?"). The `:not(pre) > code` padding/margins push surrounding punctuation away. Fix: tune inline-code horizontal margins.
- **polish — tall empty editor boxes.** Each field has a fixed `min-height: 120px`, so even single-line content shows a large empty box; the "new" screen is mostly empty space (`card-editor-new.png`). Consider auto-grow from a smaller min-height.
- **polish — washed-out disabled "Add card"** — same faded-accent disabled state as on the deck list.
- **note — field labels.** "Front"/"Back" are small (14px) and sit tight to the editor; hierarchy between label and content is shallow.

## Review (`review-question.png`, `review-answer.png`, `review-nothing-due.png`, `review-complete.png`)
- **polish — large dead space in the study card.** `min-height: 200px` leaves a big empty region below short content; question and answer hug the top-left, so the card feels unbalanced and unfinished (`review-question.png`, `review-answer.png`). Fix: size the card to content with comfortable padding, or center vertically.
- **bug-ish — keyboard hints are nearly invisible and cramped.** The "space" hint after "Show answer" and the "1/2/3/4" digits on grade buttons use `opacity: 0.45` immediately adjacent to the labels, reading like rendering noise (`review-question.png`, `review-answer.png`). Fix: deliberate, legible hint affordance (kbd-style chip, consistent placement, higher contrast).
- **bug-ish — "Back to deck" / "End session" have no visible affordance.** The `btn-ghost` links render as plain black text (transparent border + background), indistinguishable from a label (`review-complete.png`, `review-nothing-due.png`, and "End session" on the active screen). Fix: ghost buttons need a visible affordance (hover, subtle border, or underline) so they read as actions.
- **polish — bare completion / nothing-due states.** A single centered muted line plus a text-like link floating in a vast empty page; the 🎉 is the only weight (`review-complete.png`, `review-nothing-due.png`). Fix: stronger completion state — cards-done summary and a clear primary button.
- **note — no flip animation.** Revealing the answer swaps content instantly with no transition. The roadmap explicitly wants card-flip motion (confirmed by the static front/back captures and `ReviewPage.tsx`).

## Cross-cutting (tokens, type scale, color, spacing, motion)
- **note — thin token system.** `styles.css` has only `--radius`, one `--shadow`, a small color set, and a single accent. There is no spacing scale, no type-scale tokens, and the per-grade colors are ad-hoc hexes. The redesign should add a spacing scale, a modular type scale, and semantic color roles (accent / success / warn / danger) that the grade colors derive from.
- **polish — loose, inconsistent vertical rhythm.** Tall header bar, large gaps before content, oversized empty card/editor regions — screens read as sparse/unfinished rather than calm. Define one consistent spacing rhythm.
- **polish — shallow type scale.** Page title 24px, header 20px, body 14–18px; hierarchy is flat. Establish a clearer scale.
- **polish — app-wide disabled and ghost-button treatments** (see deck-list and review items) are pattern-level problems, best fixed once as tokens/components rather than per screen.
- **note — light-only.** `color-scheme: light` with no dark mode. Out of scope to implement now, but the token work should not preclude it.
